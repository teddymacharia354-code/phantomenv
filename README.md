# phantomenv 

Your codebase is probably leaking secrets right now. You just don't know it yet.

An AWS key tucked inside a config file. A database password committed three months ago and long forgotten. A Stripe live key sitting in a `.env.backup` nobody remembered to delete. These things happen to careful developers, experienced teams, and people who absolutely knew better. They happen because secret leaks are quiet — no error, no warning, no red flag until someone else finds it first.

phantomenv finds them before that happens.

---

## What it does

phantomenv scans your project for accidentally exposed credentials and secrets — before you push to GitHub. It checks your working files, your structured config files, and your entire git commit history. Anything that looks like a real secret gets flagged, masked, and reported with enough context to act on it immediately.

It catches:

- AWS, GCP, and Azure credentials
- API keys for OpenAI, Anthropic, Stripe, Twilio, SendGrid, Slack, Discord, Google, GitHub, GitLab, and more
- Database connection strings (Postgres, MySQL, MongoDB, Redis, and others)
- Private key blocks and PGP keys
- JWT tokens and OAuth tokens
- npm and PyPI publish tokens
- Generic hardcoded passwords and secrets
- High-entropy strings that look like secrets even without a known format
- Backup `.env` files that should never exist

Everything it finds is masked in the output — you see enough to identify the leak, never enough to expose it further.

## Installation

phantomenv is a single Python file. No package manager, no build step, no dependencies required to run.

```bash
git clone https://github.com/yourname/phantomenv
cd phantomenv
python phantomenv.py .
```

For the full feature set including git history scanning and YAML config support, install two optional packages:

```bash
pip install gitpython pyyaml
```

Without them, phantomenv still scans your working tree and all pattern matching still works. It just skips git history and YAML parsing.

## Usage

```bash
# Scan the current directory
python phantomenv.py .

# Scan a specific project folder
python phantomenv.py /path/to/project

# Skip git history (faster, working tree only)
python phantomenv.py . --no-git

# Skip entropy analysis (reduces noise on projects with lots of hashes)
python phantomenv.py . --no-entropy

# Only surface critical findings (useful in CI pipelines)
python phantomenv.py . --only-critical
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | Clean — nothing found |
| `1` | Secrets detected |
| `2` | Invalid arguments |

The exit codes are CI-friendly by design. Drop phantomenv into any pipeline and it will break the build if it finds something.

## Pre-commit hook

The best time to catch a secret is before it ever touches git history. Install phantomenv as a pre-commit hook and it will automatically scan your staged files on every commit:

```bash
cp pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

If it finds a secret, the commit is blocked. Fix the finding, then commit again. It only scans staged files so it stays fast regardless of project size.

### Using the pre-commit framework

If your project uses the [pre-commit framework](https://pre-commit.com), add this to your `.pre-commit-config.yaml`:

```yaml
repos:
  - repo: local
    hooks:
      - id: phantomenv
        name: phantomenv secret scan
        entry: python phantomenv.py
        language: python
        pass_filenames: false
        args: [".", "--no-git"]
```

## Suppressing false positives

phantomenv ships with false-positive reduction built in. Lines containing words like `example`, `placeholder`, `changeme`, `TODO`, or angle-bracket variables like `<YOUR_KEY_HERE>` are automatically ignored for generic patterns.

For anything that slips through, use `phantomenv.yaml` in your project root. Every finding includes a short fingerprint in the output — copy it and add it to the config to silence that specific result permanently.

```yaml
ignore:
  # Suppress by file path (supports * and ** globs)
  paths:
    - "tests/fixtures/*"
    - "docs/**"

  # Suppress an entire detection rule
  patterns:
    - "Generic Secret / Token"

  # Suppress one specific finding by its fingerprint
  fingerprints:
    - "a1b2c3d4e5f6a7b8"
```

Fingerprint suppression is surgical — it silences exactly one finding in exactly one file without affecting anything else. It is the right tool for legitimate secrets in test fixtures or documented examples.

## How entropy detection works

Not every secret follows a known format. A random 32-character token generated by an internal service, a base64-encoded credential, a custom signing key — none of these match a named pattern. They would slip through any purely signature-based scanner.

phantomenv computes the Shannon entropy of long alphanumeric tokens on every line it reads. Entropy measures randomness. Real secrets generated by cryptographic functions score high — typically above 4.5 bits per character. Human-readable strings like variable names, comments, and English text score low. Anything above the threshold that isn't already caught by a named pattern gets flagged as a high-entropy string with its entropy score shown in the output.

This can be disabled with `--no-entropy` if your codebase contains a lot of hashes or encoded data that produces noise.

## .gitignore awareness

Files matched by your `.gitignore` are still scanned — a secret in an ignored file is still a secret — but their severity is automatically downgraded. A critical finding in an ignored file becomes high. A high finding becomes medium. This keeps the report honest without burying findings that genuinely matter.
